## B001 — invalid-schema fixture declared both `bits` and `bytes`

**Milestone:** M1
**Found by:** `tests/test_schema.py::test_invalid_schema_is_rejected[char_not_byte_multiple]`

The fixture meant to exercise "a `char` field must be a whole number of bytes"
was generated by overlaying `bits: 12` onto a field that already carried
`bytes: 4`. It was rejected — but by the earlier "specify exactly one of 'bits'
or 'bytes'" check, so the rule it was written to cover was never reached.

This is the failure mode the `# expect:` line in each fixture exists to catch:
asserting only that loading *raises* would have passed. Asserting *which*
message comes back did not.

**Fix:** dropped the stray `bytes: 4` from
`schemas/invalid/char_not_byte_multiple.yaml`.

**Regression:** the same parametrised test — every fixture must produce the
message its own header declares.
